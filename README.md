기존 한자 단어 학습 웹페이지에 **단어 시험 기능**을 추가해줘.

### 1. 시험 페이지 생성

* 시험을 볼 수 있는 **새로운 HTML 파일**을 하나 추가한다.
* 기존에 저장되어 있는 한자/한문 단어 데이터를 시험 페이지에서도 사용할 수 있도록 연결한다.
* 시험 페이지를 별도의 화면으로 구성한다.

### 2. 시험 문제 출제 방식

* 등록되어 있는 한자/한문 단어 중 하나를 **무작위로 선택**하여 화면에 보여준다.
* 화면에는 문제로 한자를 표시하고, 사용자가 답을 입력할 수 있는 입력창을 **2개** 만든다.

  * 뜻 입력칸
  * 음 입력칸
* 사용자가 입력한 뜻과 음을 기존 데이터의 정답과 비교한다.
* 뜻과 음이 모두 올바르면 **정답**으로 처리한다.
* 하나라도 올바르지 않으면 **오답**으로 처리한다.
* 정답/오답 결과를 사용자가 즉시 확인할 수 있도록 표시한다.
* 다음 문제로 넘어갈 수 있는 기능을 추가한다.

### 3. 다의어 처리

한자는 하나의 뜻만 가지고 있지 않고 여러 뜻으로 사용될 수 있으므로 **다의어를 고려하여 채점**한다.

예를 들어 하나의 한자에 여러 개의 올바른 뜻이 등록되어 있다면:

* 사용자가 입력한 뜻이 등록된 뜻 중 **하나라도 의미상 올바른 경우 정답**으로 인정한다.
* 단순히 문자열이 완전히 동일한 경우만 정답으로 판단하지 말고, 기존 데이터에 등록된 해당 한자의 **뜻/음 범위 안에 포함되는 답**이라면 정답으로 처리한다.
* 음 역시 여러 발음이 가능한 경우 등록된 올바른 음 중 하나와 일치하면 정답으로 처리할 수 있도록 한다.
* 띄어쓰기, 불필요한 공백 등으로 인해 정답이 오답 처리되지 않도록 입력값을 적절히 정리한 후 비교한다.

가능하다면 데이터 구조 자체도 여러 뜻과 음을 저장할 수 있도록 확장성을 고려해서 구현한다.

### 4. 새로 추가된 단어도 시험에 포함

* 사용자가 기존 페이지에서 **새로운 한자나 한문 단어를 추가하면 해당 데이터도 시험 문제에 자동으로 포함**되어야 한다.
* 시험 페이지에서 별도의 단어 목록을 따로 관리하지 않는다.
* 기존 단어 데이터와 시험 데이터가 동일한 데이터를 사용하도록 구현한다.
* 따라서 한자/한문이 추가되거나 수정되면 시험에도 자동으로 반영되어야 한다.

### 5. '시험보기' 버튼 추가

기존 메인 페이지의 버튼 영역에 **'시험보기'** 버튼을 추가한다.

버튼 조건:

* 버튼에 표시되는 글자는 **'시험보기'**
* 버튼을 클릭하면 새로 만든 시험 페이지로 이동
* 버튼 위치는 기존 **'초기화' 버튼과 '햄버거 메뉴' 사이**
* 버튼의 배경색은 **빨간색**
* 기존 UI와 어울리도록 글자 크기, 버튼 크기, 모서리 등의 스타일을 적용한다.

버튼 배치는 다음 순서가 되도록 한다.

**[초기화] → [시험보기] → [햄버거 메뉴]**

### 6. 기존 기능 유지

* 기존 단어 추가, 수정, 삭제, 초기화 기능은 그대로 유지한다.
* 기존 UI나 기능을 불필요하게 변경하지 않는다.
* 새 기능을 추가하면서 기존 데이터가 삭제되거나 초기화되지 않도록 한다.
* PC와 모바일에서도 시험 페이지가 정상적으로 작동하도록 한다.

### 7. 구현 시 중요한 점

* 시험 문제는 매번 가능한 한 **무작위로 출제**한다.
* 현재 등록된 전체 한자/한문 데이터를 기준으로 문제를 출제한다.
* 데이터가 추가되면 시험 문제에도 자동으로 반영된다.
* 다의어/다중 음을 고려하여 너무 엄격한 문자열 비교 때문에 올바른 답이 오답 처리되지 않도록 한다.
* 기존 코드의 데이터 저장 방식이 있다면 그것을 최대한 재사용하고, 같은 데이터가 메인 페이지와 시험 페이지에서 공유되도록 구현한다.

**최종적으로 사용자가 메인 화면에서 '시험보기'를 누르면 시험 페이지로 이동하고, 등록된 한자가 무작위로 출제되며, 뜻과 음을 입력해서 정답 여부를 확인할 수 있도록 구현해줘.**
